> 这是一篇用于展示博客功能的示例文章。站点已保留 MDX 支持，但日常写作优先使用普通 Markdown。

MDX 允许在 Markdown 中嵌入组件。它适合真正需要交互或结构化展示的内容，而不是替代所有文章写作方式。

## 为什么保留 Markdown

纯文本具有很长的生命周期。标题、列表、引用和代码块不依赖特定前端框架，也便于版本管理。对大多数文章而言，Markdown 已经足够。

```md
## 一个小节

普通文字、**重点**与[链接](https://astro.build)。
```

## 什么时候使用 MDX

当内容需要复用站点组件，或需要展示无法由标准 Markdown 表达的结构时，MDX 才有明显价值。

1. 可交互的数据展示；
2. 需要统一样式的提示模块；
3. 在同一篇文章中重复出现的复杂结构。

## 保持内容可维护

组件越多，文章与代码的耦合越强。新增组件前，可以先问：这段内容是否仍能脱离组件被理解？构建失败时，是否能快速定位？

技术选择的目的不是展示能力，而是让表达更准确，同时把长期维护成本留在可接受的范围内。
